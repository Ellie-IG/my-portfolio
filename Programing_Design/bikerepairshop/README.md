# Bike Repair Shop

A point-of-sale and workshop management system for a bicycle repair shop, built as part of the course IV1350 Object-Oriented Design at KTH.

## What it does

The system supports the full workflow of a repair shop visit:
- Register a customer and their bike
- Log faults found on the bike and propose repairs
- Apply discounts based on customer type (Strategy pattern)
- Process payment and print a receipt
- Log errors and unexpected states to file

## Architecture

The code follows a layered architecture with clear separation of concerns:

| Package | Responsibility |
|---|---|
| `startup` | Application entry point (`Main.java`) |
| `controller` | Coordinates calls between the view and the model/data layers |
| `view` | User-facing display and interaction |
| `model` | Core domain logic (repair orders, tasks, faults, order state) |
| `data` | Domain entities (`Customer`, `Bike`) |
| `dbhandler` | Simulated database access and registries (incl. a Singleton customer registry) |
| `payment` | Discount calculation using the Strategy pattern (`Discount0/15/20`) |
| `printsystem` | Formats and prints receipts |
| `logger` | File-based logging of errors and events |
| `exeptionhandler` | Custom exception types for domain-specific error handling |

Design patterns used include **Strategy** (discount calculation), **Singleton** (customer registry), **DTO** (data transfer between layers), and **Observer** (repair order state changes).
